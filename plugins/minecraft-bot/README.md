# Minecraft 机器人（minecraft-bot）

把 Agent 接入 Minecraft Java 版：机器人连上服务器后，你可以在游戏聊天框直接和它说话，也能让它移动、跟随、攻击、挖矿、农耕、交易。

## 0.11.0-beta.1 更新说明

相对 0.10.0-beta.1 有三组变化：

1. **出站文本治理**：模型回复洗成游戏聊天栏可读的纯文本，长回复按行分条并收口，中途掉线如实报告。
2. **密码登录插件支持**：服务器装了 ServerPassword / AuthMe 时可在面板填密码与登录命令。
3. **26.2 / 26.3 支持（实验性）**：需要按下面的「构建运行时」为运行时打补丁，**不打补丁时行为与 0.10.0-beta.1 一致**（官方 npm 依赖栈只到 26.1）。

配置格式与工具参数没有破坏性变化：新增的都是可选项（面板里的「协议版本 / 服务器密码 / 登录命令」，以及工具的 `protocolVersion` 参数），留空即维持原有行为。

## 功能

- 游戏聊天双向：玩家说话进 Cyrene 对话，她的回复发回游戏聊天栏。
- 第一人称情境：每轮把坐标、生命、饥饿、背包、近期游戏聊天注入提示词。
- 动作工具：移动、跟随、停下、进食、装备、放置、挖掘、攻击、拾取、开门、到指定方块、下挖、上地表、丢弃、耕地播种、箱子存取、村民交易、建造庇护所等。
- 自主任务：用自然语言委托多步目标，进度在游戏里汇报。
- 本能反射：饥饿自动进食、受击反击或逃跑（可开「胆小模式」）。

## 启用与配置

1. 在 Cyrene 的「功能插件」里启用本插件，打开配置窗口。
2. 填写服务器地址、端口、角色名；连 26.2/26.3 时确保运行时已按下一节构建。
3. 点「连接」，之后即可在游戏里对话。

| 配置项 | 说明 |
| --- | --- |
| 地址 / 端口 | 目标 Java 版服务器；地址里写 `host:port` 也能识别 |
| 角色名 | 不超过 16 字符 |
| 协议版本 | 留空即自动探测；填数字（如 `777`）可强制指定 |
| 服务器密码 | 仅在服务器装了密码登录插件时填；不持久化，重开窗口需再填 |
| 登录命令 | 配合上一项，默认 `/serverpass {password}`，AuthMe 一般填 `/login {password}` |
| 胆小模式 | 开启后见到敌对生物逃跑、不反击 |

服务端要求：`online-mode=false`；`white-list=false` 或把角色名加进白名单（26.3 默认配置是 `white-list=true` 且名单为空，会把机器人挡在外面）；`enforce-secure-profile=false`。26.3 服务端需要 Java 25。

## 支持的版本

| 运行时 | 可连的 Java 版 |
| --- | --- |
| 仅 `npm install`（未打补丁） | 1.8.8 — 26.1 |
| `npm install` + `npm run patch:263` | 1.8.8 — **26.3**，含 **26.2** |

### 版本自适应（「协议版本」留空时）

连接前先做一次 SLP 探测，**以协议号为映射依据**，不用服务端自报的版本名——Paper 报的是 `Paper 26.3` 这类带前缀的字符串，按名字比对必然失配。

| 探测结果 | 行为 |
| --- | --- |
| 协议号能映射到已收录版本 | 锁定该版本连接 |
| 协议号比已知最新版本还新 | 按已知最新版本试连，并在日志里提示可能出现方块 id 错位 |
| 协议号无法映射 | 回落到 mineflayer 的自动协商 |
| 探测本身失败（端口不通、超时） | 记一条日志后回落到自动协商，不抛错 |

## 构建运行时

26.2/26.3 的支持不在插件代码里，而在依赖栈上。仓库只收录源码，运行时由打包者按下面步骤生成：

```bash
cd runtime/bot-runtime
npm install
npm run patch:263          # 打 26.2/26.3 支持，末尾自带自检，失败即中止
cd ../..
npm --prefix runtime/bot-runtime run prepare-runtime   # 裁剪数据后产出可分发的运行时
```

`scripts/patch-minecraft-263.mjs` 做四件事：把 mineflayer 换成钉死的 master 快照；按 sha256 校验后套用 13 个上游 PR 的 diff（用脚本自带的 diff 应用器，不依赖 git）；补四处 npm 版上下文对不上的手工改动；重生成 minecraft-data 的 `data.js` 索引。任何一步非预期失败都会中止，不会留下半成品。`npm run patch:263:pin` 只重新打印 tarball 哈希，供更新钉点时用。

需要 `tar`。若 `fetch` 报 `UNABLE_TO_VERIFY_LEAF_SIGNATURE`（本机根证书不在 Node 默认信任链里），改用 `node --use-system-ca scripts/patch-minecraft-263.mjs`。

### 为什么要那个限速

26.3 原版服务端限制「每个客户端 tick 只允许一个带位置的包，收到 serverbound `tick_end` 才复位」。mineflayer 的 `tick_end` 修复（#4137）只在每个物理 tick 末尾发一次，而出生/传送那一个 tick 里会连发 `teleport_confirm`、`position_look`、`position` 三个带位置的包——实测不打限速时 **8 轮里 6 轮在约 0.65 秒被 `invalid_player_movement` 踢出**；打上限速后 **8/8 存活**，另有 3 轮 × 20 秒连续移动跳跃（每轮 137–228 个位置包）无一被踢。

## 出站文本治理

频道声明 `markdown:false` 只是告诉宿主「我不支持富文本」，宿主不会替插件转换，所以清洗必须在出站做。`channel.js` 里的 `toGamePlainText()` 与 `wrapForGameChat()`：

- 剥掉 `**粗体**`、`*斜体*`、`__x__`、`~~删除~~`、行内反引号、代码围栏（保留围栏内的内容）、`#` 标题、`>` 引用、`---` 分隔线；`- ` / `* ` / `1. ` 列表统一成 `· `；`[文字](链接)` → `文字（链接）`，图片只留 alt。
- GFM 表格摊平：分隔行丢掉，两列表写成 `键：值`，多列表用顿号连接。游戏聊天栏没有等宽对齐，原样发出只会是一串竖线。
- 每行 256 上限改为优先在句读或空格处折行，整段确实没有断点时才硬切；单次回复最多 10 条（含提示行），超出补一行「…（回复过长，余下 N 行省略）」。
- 逐条发言间隔 1.2 秒。原版服务端每发一条聊天给 `chatSpamTickCount` 加 20、每 tick 减 1，累计超过 200 就以 `disconnect.spam` 踢人，等价于持续超过 1 条/秒必掉。实测 350ms 间隔发到第 16 条就被踢下线。
- 每条发送前重查连接状态：中途掉线时返回 `{ok:false}` 并写明剩余几行没发出，宿主据此记失败回执，不会把半截回复当成已送达。

对照输入 `**我走到你身边了**，顺手挖了 3 个橡木原木：` + 列表 + 代码围栏 + 链接 + 删除线，游戏里实际收到：

```
我走到你身边了，顺手挖了 3 个橡木原木：
· 木板 x2
const x = 1;
传送（https://a.b/c） 和 code 以及 删除
```

## 服务器装了密码登录插件

离线服通常靠 ServerPassword / AuthMe 这类插件挡冒名进来的人。填了「服务器密码」才发登录命令，留空即按无密码处理。

发送时机是实测出来的：26.3 原版服务端在 `login` 事件刚响时收到的命令包会被丢掉，出生前后 1—8 秒发都有效。所以安排在第 2 秒首发；若到点还没出生（密码插件通常不放行）就按 4/7/11/16 秒补发。首次发送不看出生信号，因为 AuthMe 是先进世界再冻结操作，等出生信号就永远不会发了；只有补发才以出生为停止条件。

## 网络与存储行为（供审核）

- **运行期网络**：只连接用户在面板/工具里填写的 MC 服务器地址端口，不访问其它域名，不上传对话内容到第三方。
- **构建期网络**：`patch-minecraft-263.mjs` 访问 `github.com` 与 `codeload.github.com` 下载钉了 sha256 的 tarball 与 PR diff，校验通过才落地。运行期不涉及。
- **子进程**：插件启动一个 Node 子进程运行 `runtime/bot-runtime/src/index.mjs`，通过 stdio JSON 行协议通信；参数全部来自面板输入并经长度/格式校验；停用或退出时结束该子进程并清理计时器。
- **文件读写**：只写插件自己的 `ctx.storage`（连接配置、胆小模式偏好）。
- **密码处理**：服务器密码只在本次连接的内存里，**不写进 `ctx.storage`**（宿主插件存储是明文 JSON），不进日志，也不进喂给模型的「最近游戏聊天」缓存——部分登录插件会把命令原文回显到聊天栏，因此日志出口、缓存和订阅回调都做了 `***` 替换。工具 `minecraft-bot_connect` 不接收密码参数，避免让模型经手密码。断线自动重连复用内存里的同一份配置。
- **依赖声明**：`manifest.json` 只声明 `llm`，未新增能力。

## 已知限制

- **26.3 支持依赖上游尚未合并的 PR**。上游一旦合并并发新版，`patch-minecraft-263.mjs` 就该删掉，届时只需 bump 依赖版本 + 保留 `26.2/26.3` 数据白名单 + 打包时重生成 `data.js`。在合并前，钉点哈希过期时脚本会拒绝执行，需要人工复核后更新钉点。这也是这一半功能标为「实验性」的原因。
- 正版验证服务器（`online-mode=true`）不支持；会改游戏机制的模组服务端不支持。
- 26.3 上已实机验证：连接、出生、聊天、寻路、挖方块、拾取、背包上报、放置、Paper 云服 + ServerPassword 全链路。**未**逐项验证：合成、熔炼、村民交易、耕种、床、箱子交互。「比已知版本更新时按最新版本试连」这条分支是设计推演，还没有真实的新版本服务端可测。
- 老版本（1.8.8 — 1.21.x）在这份改动上未重新实连，依赖的是官方构建已跑通的部分；只有上界因补丁而变化。
- 出生竞态的根因在 mineflayer 的 tick 记账（传送回显绕过了 tick 边界），本插件是在外层拦一层，不是上游修复。
- 单次回复上限 10 条是按「不被服务器刷屏保护踢线」倒推的，代价是长报告尾部截断（游戏里看到省略提示，完整内容仍在桌面对话里）。
- 被踢线后不会自动重连，需要在配置窗口重新点「连接」。
- 插件注册渠道的消息投递依赖宿主转录写入侧接受非内置渠道 id。若宿主把渠道枚举写死成内置几家，送达回执写入会抛 `TRANSCRIPT_CORRUPT_ROW`，调度器按 fail-safe 禁止发送——表现是模型确实跑完并调了工具，游戏里却收不到回复。插件侧无法绕过，详见 PR 说明。
